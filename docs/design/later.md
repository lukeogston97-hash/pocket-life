# Planned and not built yet: sign-in, buildings, later ideas, stone

- Sign-in (decided 21 Nov 2026, not built yet): Google sign-in later, optional, so the same person works on phone and PC; signing in keeps the person you already have. The server's whoFor(m) in index.js is where it plugs in (map 'acct:<google id>' to the phone's who). Luke makes the Google Cloud web client ID when we build it.
- Buildings: not built yet; use the placeables system.
- Later: everything saved on the server, day planner, skills, more stats, regions and time zones, app store wrapper.
- Stone (0.2.9, Luke): loose stones are picked up by hand and still top up as a safety net. Rocks need the stone pickaxe: Break rock gives 5 stones and the rock is gone, but one broken rock comes back (same spot, beside its boulder) every mining.rockBackHours (4). Boulders are permanent and can't be removed: Mine boulder gives 3-5 stones, then it looks worn down and can be mined again after regrowDays (3, same as trees). Later: better pickaxes, ore, quarries; maybe slow the loose-stone top-up once mining is the main source.
- Societies (decided with Luke 23 Nov 2026, not built yet): keep the main worlds run by the admin; no player-run worlds. Societies are player groups inside the main world (a name, members, maybe a leader, a shared camp, storage and land). Build them after storage and shelter, since they need those (and trading).
- Campfire claims: built in 0.3.0, see claims.md. Still to come with societies: members sharing their society's claim, and storage inside a claim going back to the world when it lapses. Luke's first idea was about 50 m per claim, for when worlds are 1 km.
- Bigger world (Luke, 23 Nov 2026, eventually): worlds of 1 km square. Needs the game to only draw what's near you (its own update). The current 100 m stays exactly as it is; new land gets its own random seed.
- Fishing and cooking (0.3.4, Luke 23 Nov 2026; no wheat or bread, fish is the first food): the pond has a Fish action (sources.pond.fish in game-data.json). Tap the pond, Fish, needs a fishing spear (20 uses, wears each try). A try takes 8 s and catches a fish about half the time (chance 0.5), costs 3 stamina. The pond holds 10 fish for everyone (the server keeps w.pond { fish, at }, one comes back every 60 minutes, worked out when someone fishes; Admin > World > Regrow everything refills it). The game doesn't know the count: the server replies 'fished' with what happened (caught, Nothing bites, No fish left, Too heavy). Raw fish can't be eaten; a recipe with near campfire and seconds 20 makes Cooked fish (35 hunger, a berry gives 10); recipes with seconds use their things up when they finish. Fish is a new item shape (SHAPES.fish). Away people don't fish. Later, as one "keeping food" update with storage: food going off (raw about a day, cooked about 3 days, dried a couple of weeks) and a drying rack.
- Walking to the pond (0.3.4): the shore point must be dry ground walking allows (pondShape at least 0.9), or the walk to drink or fish could get stuck with Can't get there.

## From the whole-game check before public testing (24 Nov 2026): not done, for Luke to decide
Fixed and published that morning (see docs/design/code.md): things that aren't in the world, names and chat nobody can read, names every object has. Left as they are, smallest first:
- A campfire can be put in the pond or inside a tree by a changed game (the server checks distance, claims and other placed things, not the land). Looks only.
- Building and cooking take time in the game but the server doesn't time them, so a changed game could skip the wait.
- A rock can be mined "as a boulder" and a boulder "as a rock" (the game says which; the server doesn't know which rocks are boulders). A boulder mined as a rock vanishes for everyone until rocks come back (one every 4 hours). Fix: the layout carries which rocks are boulders.
- A brand new world takes how many berries a bush holds (1 to 15) and how fast they grow back from the first game in. From admin mode the admin's game is first in after a reset, which covers it in practice. Fix: the server uses its own numbers.
- Loose items never go away by themselves (sticks top up to their cap, but dropped and chopped things stay for ever). Over weeks the ground fills and every phone has to draw it. The admin's Clear loose items is the only broom. Idea: things left lying for some days fade.
- A ban is by the phone's id (a random id the browser keeps). Clearing the site's data makes a new one. Known limit of having no sign-in.
- At the player limit (20 playing all day, 300 away) the server uses about 81,000 of the free 100,000 storage writes a day (tools/tests/load.py 300). Fine for now; see docs/design/code.md for the ideas if it grows.
