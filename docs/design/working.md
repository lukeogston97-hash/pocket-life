# Working on it: versions, testing, releasing, checks

- Build in SMALL steps: Luke asked for just a couple of things per update from 0.0.7 on. After each change, tell Luke in a few short lines what changed and what to try on his phone.
- Versions are Major.Minor.Patch (Luke, 23 Nov 2026: numbers were climbing too fast). Luke then had them reset lower the same day: 0.3.8 became 0.1.0, and everything before is folded into one "0.0.x" early builds entry in What's new. game-data.json has "era" (now 1) so games from before the reset still count as older: the server checks era first (worlds.json keeps each link's era, tools/worlds.py sets it). Only raise era if numbers are ever reset lower again. tools/release.sh keeps the newest 3 copies by when they were released, not by number.
  - Major: 1.0.0 is the full game launch. Stay on 0.x until then.
  - Minor: a big new update or content stage (for example farming, storage and shelter, hunting). Next one is 0.2.0. Only Luke decides when a minor bump happens.
  - Patch: one per release to players, not one per test build. It can go past 9 (0.1.10, 0.1.11).
  - Test builds: only "build" goes up (0.1.0 test 1, test 2...). After a release, the next round starts on the next patch with build 1.
  - It's only in game-data.json: "version" and "build". The page shows it, like "v0.1.0 (test 2)".
- Dev log (What's new): one entry per version, newest first, and test builds add their lines to that same entry. When a minor version is finished, fold its patches into one entry like "0.1.0 to 0.1.9" with a few highlights.
  - Format (Luke, 23 Nov 2026: cleaner and more compact, easy for players to read): each entry has "version", "date" (the release day; add "from" for a range, like the 0.0.x early builds, 21 to 23 Nov 2026), an optional "title", and its lines in "added" (shown as + : new features), "improved" (~ : changes and refinements to what's there) and "fixed" (− : bug fixes, corrections and removed issues). Only the lists it needs.
  - Lines: short (90 letters at most, one line on a computer), plain words for players, no full stop at the end, no em-dashes. Don't start them with "Added", "Improved" or "Fixed": the symbol says it. lint checks the format.
  - The panel shows a small key (+ Added, ~ Improved, − Fixed), the newest version open, then the rest under Version history, each with its release date. It's in openNews in game/online.js.
  - Some changes get no entry when Luke says so (the admin rework, this dev log format change).
- To test needs quickly, raise settings.needsSpeed (60 makes an hour pass in a minute). Put it back to 1 before pushing.
- game-data.json is loaded with fetch, so opening index.html straight from the disk won't work. Test with a local server (python3 -m http.server) or the test link.
- Test first, then release. Make every change in the test/ folder, push it to main, and tell Luke to try it on the test link: https://pocketlife.pages.dev/test/
- Each new test build: bump "build", then run python3 tools/worlds.py test-build so older test games move to it.
- Maintenance: Luke switches it on and off himself in the game (Admin in the Menu). Release-link players see a Back soon screen, needs pause, and it rejoins by itself. The test link still gets in, so Luke can try the new build first.
- server/worlds.json holds the minVersion for each link. Older games get sent to the newest version (they wait and retry if the link hasn't updated yet).
- Only when Luke says to release it ("release", "publish"), run sh tools/release.sh (it keeps only the newest 3 copies in releases/; it also sets the release link's minVersion to version.build, so a patch moves everyone on too; Luke turns maintenance off in the game), then commit and push. It copies test/ to the root (the release link: https://pocketlife.pages.dev/) and keeps a copy in releases/<version>/ so we can roll back.
- Push to main, not only to a separate branch, or neither link updates. The game's home is Cloudflare Pages (project pocketlife, https://pocketlife.pages.dev/, set up 22 Nov 2026), which rebuilds from main about a minute after each push. The old GitHub Pages address (lukeogston97-hash.github.io/pocket-life/) still updates too, but its index.html sends people to pocketlife.pages.dev with the phone's id after # so they keep their person (0.1.7).
- Before pushing a change, run the checks, kept quick (Luke, 22 Nov 2026): lint always, then only the checks for the area you touched; releases add `run.py quick`; everything (`run.py`, which skips `screens`) only after big changes (see tools/tests/README.md; first time `cd tools/tests && npm install`). The layout check must pass: the world's layout can never move. Add a check for each new feature in tools/tests/checks.py.
- Checks since 0.3.0: lint.py first runs `tools/worlds.py check` (game-data.json mistakes, and the server's copies being up to date). New checks: admin_tools, claims, guards (reach, no jumping, admin code lockout), maintenance (needs pause) and reconnect (a pick-up made while offline is sent on reconnecting). The local test server now handles one message at a time, as Cloudflare does. After changing test/game/rules.js run test-build too (it copies it to the server).
- Checks since 0.3.0 build 2 and 0.3.1: reset_all (Admin, Reset everything), errors (a broken frame doesn't freeze the game and the Inbox gets one note) and crowd (40 people away: only the nearest few get a body). `run.py` with everything now takes about 35 minutes. tools/tests/load.py is the server load test (see tools/tests/README.md).
- No em-dashes in anything Luke reads.
