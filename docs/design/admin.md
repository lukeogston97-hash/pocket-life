# Admin: admin mode, the dashboard and live settings

## Admin mode (24 Nov 2026, Luke: one big update built overnight, no devlog entry, same version)
- The admin is no longer a player. Nobody playing a person can be the admin, and the old `/admin` in the Say box is gone. On the server the admin is only a connection that watches with the code and has no person (`isAdmin(me)` in server/src/index.js). A playing connection that still carries an old admin flag has it dropped before anything reads it.
- Way in: tap the version number on the main menu 5 times (each tap within 4 seconds of the last), then type the admin password. It is asked every time and never kept on the device: only in memory while admin mode is open, and Exit admin forgets it. 5 wrong passwords in 15 minutes lock that address out for 15 minutes.
- Other ways to the same password box (24 Nov, Claude's additions so the admin is never locked out; say if you'd rather not have them): `?admin` on the end of the address opens the box when the game loads (for a device where five quick taps are awkward; it only opens the box, the password is still the lock). While maintenance is on, the main link shows Back soon to everyone and the main menu is behind it, so there 5 taps on the words "Back soon" open the box (the test link's main menu still works as normal). Before admin moved out of the game, a phone that remembered the password could always get in during maintenance; this keeps that.
- A refused password is never kept or sent again: the server says no before it sends the game away for maintenance or an update.
- On touch screens the version number and "Back soon" take quick taps as taps, never a zoom, and every box the admin types in is 16 px (an iPhone zooms the whole page in on a smaller one; the game's own Say and name boxes were already 16 px).
- What it is: a watch view of the live world with no person, with a free camera. On a phone: one finger slides the view, pinch zooms, two fingers twist to turn. With a mouse: drag turns the view, right-drag (or Shift and drag) slides it, the wheel zooms, and W A S D slide, Q E turn, R F tilt. A top bar (Admin, world and time, counts, Dashboard, Exit) and the Dashboard: a dock on the left on a computer, a sheet from the bottom on a phone (700 px wide or less). The game code is test/game/admin-mode.js (the way in, camera, taps) and test/game/admin.js (the dashboard and tools).
- Tap anything in the world for what can be done with it: the ground (Add item, Fly here), a person (their page, fly to, follow, move, fill needs, mute, kick, ban), a loose item, a tree, stump, rock or bush, a campfire (move, fill with fuel, light or put out, end claim, remove).
- Dashboard tabs: Server, Players, Inbox, World, Settings, Items, Log. They sit in rows of four, so a new tab just joins the last row.
- New feedback or a report shows a line under the bar only in admin mode (Luke: "Only in admin mode").
- Switching worlds: not built yet (Luke: "not need just yet"). The top bar already names the world, which is where a switch would go.
- From the first mockup, not built: a panel for the selected thing (tapping it opens a menu instead), a map, camera modes, and usage and Maintenance in the top bar (both are on the Server tab).
- Rule from now on (Luke: "as new thing get added the admin pannel needs to update as well"): every update that adds something adds the admin's control for it in the same update. docs/adding.md says how for each kind of thing. New items, recipes and live settings show up in the dashboard by themselves.

## Changing numbers live: what wins
- game-data.json is where every number starts. A change the admin makes sits on top and wins, also over a new build, until its Reset is tapped. A changed number says "Changed (was X)". (Luke asked what the source of truth is when a tool's weight is set in the file and then edited in admin: the admin's edit, until Reset.)
- Settings tab: the live settings (server/src/live.js), as before.
- Items tab (server/src/live-items.js, storage key `liveItems`): an item's weight, a tool's uses, how much a food fills, and how many of each thing a recipe needs and makes. Every game gets the new numbers straight away. Not changeable there: names, looks, new items or new ingredients, and how many of an item lie about in the world (`startInWorld`).
- Copy my changes: lines like `items.knife.weight: 1 -> 4`, to send to Claude. Claude writes them into game-data.json, then they are Reset in admin. That is how a change becomes permanent.

## People (admin mode)
- A person's page also shows their task list as the server has it (what they carry on with while away, 0.1.7), with Clear task list (two taps; their game stops too if they're playing).
- A person's page: needs as bars, and Edit needs and age opens boxes to type in. Needs go 0 to 100, health never below 1 (typing can't kill: Remove from world is its own button), age 13 to 120 (Claude's choices, 24 Nov). Only the boxes that were changed are sent.
- Rename: any name, for one the filter missed. Their own game and everyone else's show it straight away.
- A message only they see: shown like a message to everyone, only while they're online. It isn't kept for later.
- Also there: the bag (Take 1, Take all, Give items), Fly to, Follow, Move (tap where they go), Fill needs, Mute, Kick, Wake up, Send to sleep, Ban, Remove from world.
- Moving someone who is away: they carry on by themselves from the new spot. They are not pinned there.
- Follow: the camera stays on them until the view is moved by hand or they leave. A chip at the bottom says who. Tap it to stop.

## Fires and claims (admin mode)
- World tab, Fires and claims: every fire, whose claim it is, burning or out, and the fuel left. Buttons: Fly to, Put out, Light, End claim, and under More the hours of fuel and who the claim goes to.
- The same rules as the game: one claim each, clear of the pond and of other claims, and only a burning campfire holds one (server: `claimFit` in claims.js, shared with lighting a first fire).
- Put out ends a claim on that fire, so it asks twice. End claim frees the land and the fire burns on, still its builder's to pack up. A fire with no fuel can't be lit (set its fuel first). A fire the admin lights is nobody's claim until it's given to someone.
- The owner is told when their claim ends or when they're given one.

## Societies (admin mode, 0.1.4)
- World tab, Societies: every society with its leader, how many of how many, and its claim (burning, time left). Fly to (its claim), Members (each with Take out, and a Rename box: any name, as with people), End (two taps: its fire goes out). Since 0.1.5 a claim is a society: End claim ends it (the fire burns on), and Give claim starts a new one for that person. A player's page shows their society with Take out of society. Live setting: People in a society (Settings, Players). See societies.md.

## Log (admin mode)
- Log tab (server/src/activity.js, storage key `activity`, the newest 200 lines): new people, deaths, someone back after 10 minutes or more away, someone gone after too long away, claims made, every admin tool that changes something (with its answer, also when it couldn't be done), admin mode opened, and wrong admin passwords (never the password itself). The same line again within 10 minutes is counted, not repeated. Filters: All, People, Admin, Refused.
- Few writes: one per line, and lines are rare (never one per ordinary action). Reset everything empties it. A Restore puts it back to how it was then, so the restore itself leaves no line.

## Before admin mode (kept for the history; the tools are the same, the way in is not)

- The Admin update (0.2.9 test build 2, Luke 23 Nov 2026, one big update, no devlog entry): the Admin panel has tabs Server (usage, maintenance, message everyone, speed up time with a chosen speed 10x/60x/600x and length, admin tag), Players (search by name, filters All/Online/Away/Asleep/Muted/Banned with counts, shows 50 at a time; tap someone for their page: needs, age, bag with Take 1/Take all and Give items (respects their carry limit), Teleport, Fill needs, Mute, Kick, Wake/Send to sleep, Ban and Remove from world (tap twice), reports about them, Past people from past:<who> in storage), Inbox (Feedback and Reports with a new count; Done or Delete; Done ones are deleted after 30 days), World (counts, Regrow everything: stumps, mined boulders, broken rocks, bushes, grass and sticks and stones topped up; Clear loose items near you (10 m) or the whole world (tap twice); Reset the world in a danger zone, tap twice) and Settings (live settings). Tap menus under Admin: the ground has Add item (a picker with search, the Craft kinds and 1/5/10) and Teleport here; a tree, stump, rock, boulder, berry bush or campfire has Move (then tap where it goes), Regrow (a stump to a tree, a mined boulder back, a bush full of berries, a campfire full of fuel) and Remove (asks once more; gone for good). The layout never moves: moved things are world.moved { 'tree:12': [x, z] } and drawn shifted from where they were laid out; removed trees and rocks are state gone plus world.removed (removed rocks never come back), removed berry bushes are world.removed. Live settings: liveSettings in game-data.json (names, groups, units, limits); server/src/live.js and LIVE_SET in game/admin.js wire up each id (player limit, sticks and stones respawn, berry, stump, boulder and broken rock regrow times, hunger, thirst and rest drop per hour). Saved in storage as 'live'; a live number wins over game-data.json until Reset, so a new build doesn't undo it. The game gets them in welcome and 'live' messages. Release-link games from before this don't know about moves, removed bushes or live settings until they update.
- (Until 24 Nov 2026) Admin: all in the game on Luke's phone (the admin player), not a separate page. Replaced by admin mode, above.
- 0.3.0 (from the 23 Nov 2026 audit, Luke approved all): maintenance now pauses everyone who isn't playing. Their needs, strolls, the day-asleep and 3-days-gone timers and every fire's fuel stop, and carry on from where they were when maintenance ends or they get back in (persons.js paused and thaw, admin.maintAt). People still playing (the admin, the test link) carry on as normal. The Menu's Admin button says "Admin · 2 new" when feedback or a report comes in, straight away (the server tells admins: adminNew). The Settings tab no longer redraws while you're typing a number. The panel has a title and the same Close link as Inventory and Craft, and stays one height as you switch tabs.
- Reset everything (0.3.0 test build 2, Luke 23 Nov 2026: "I want to delete all player data and reset the world"): Admin, World tab, Danger zone now has two buttons. Reset the world (as before): the land, loose items, placed things, claims and the admin's moved and removed things start again, people stay. Reset everything (`a.reset` with `all: true`): that, plus every person (`p:`), everyone's past people (`past:`), the Inbox (`feedback`, `reports`) and the ban and mute lists are deleted (Luke: "delete all player data"). It keeps live settings, speed, maintenance and its message, and today's usage count. Everyone is sent `{ t: 'reset', all }` and rejoins: they make a new person, and the first game back lays the world out fresh. It can't be undone, except with Restore (below). Both buttons need two taps, and the second tap only counts after 1 second (`twoTaps` wait), so a double tap by mistake does nothing. Only Luke can press it (the admin code). Check: `reset_all` (the local test server answers `__keys` with what's in storage, for checks only).
- Restore (0.3.2, Luke 23 Nov 2026, published straight away): Admin, World tab, Restore an earlier time. Quick picks (10 min, 1 hour, 6 hours, 1 day) or Pick a time (a date and time box, last 30 days); the button says the time (`Restore to 23 Nov, 4:32 pm`) and needs two taps (the second only counts after 1 second). The server (server/src/restore.js, `a.restore` with `at`) uses Cloudflare's point-in-time recovery (getBookmarkForTime, onNextSessionRestoreBookmark, then ctx.abort to restart), so everything goes back together: the land, every person and bag, claims, the Inbox, bans, maintenance and live settings. Everyone is sent `{ t: 'restoring', text }` (banner, queue and outbox cleared, and on rejoining they're put where the server has them), then the world restarts 1.5 s later and every game reconnects by itself. While restoring, the server ignores messages and ticks. The admin's phone gets `adminRestore` with an undo point (the moment just before the restore), kept in localStorage `pocket-life:restoreUndo`, and the World tab shows `Restored <when>, back to <when>` with Undo (two taps; `a.restore` with `undo`). Undo is used up once done (no redo; restore a time again instead). The undo point is only on the phone that restored. If a restore fails nothing changes and the Inbox gets a Server error note. If a bad server update caused the damage, roll the code back first or it happens again. The local test server keeps its own history so the `restore` check can try it.
