# Pocket Life

Luke's mobile "life in your pocket" game (SEED meets One Hour One Life): a persistent online world you check in on every couple of days. Built step by step with Claude.

**How to add things: docs/adding.md.** Every decision so far is in docs/design/, one file per area (docs/design.md lists them). Read only the file for the area you're changing. docs/history/ is only for looking back.

## Rules that always apply
- Look: soft low-poly 3D like SEED, dark glass UI, icons only, as little on screen as possible. Luke is very particular about the look: don't restyle without asking.
- One world for everyone (Oceania, Darwin time). One person per player; die and you start again in the same world. No PvP. Players 13+.
- Content goes in content/*.json, not code, wherever possible: one file per kind (items, recipes, placeables, world, rules, people, text, and version with the devlog); each file's "_help" explains its sections. test/game-data.json is made from them by `python3 tools/worlds.py test-build`: never edit it. New items must show up by themselves in Inventory, Recipes and the admin Add list; keep that true for placeables later.
- The world layout must never move (shared items, trees and bushes would stop lining up). New layout things get their own random seed.
- Stay inside Cloudflare's free plan: few messages (walks are sent once), few storage writes (save on actions, else every 5 min). The admin dashboard shows today's use.
- The admin grows with the game: anything new gets its admin control in the same update, working on a computer and a phone (docs/adding.md, "The admin grows with the game").
- Writing for Luke: short, plain words, bullet lists with "- ", no em-dashes. Ask questions with tappable options, one at a time when he asks for that.
- Words players see follow docs/design/wording.md, not the style above: friendly full words, camp (never claim or society), "+10 food", item names lower case mid-line, the same words in the tap menu and the task list.

## Where things are
- test/ is the next version: index.html (page, loading screen and loader), style.css, game/*.js (the code: ES modules, one file per topic), game-data.json (made from content/), vendor/ (three.js r170, kept with the game), icons/ (the app icon and the picture a shared link shows, redrawn from the game by tools/tests/pictures.py), manifest.webmanifest and privacy.html (Privacy and rules: a page of its own, and the words Settings shows; keep it true when the game keeps something new). The root is the released copy (tools/release.sh makes it; never edit it, and search test/ not the root). Every release is its own commit, so rolling back is reverting that commit. robots.txt (root only) keeps test/ and the project's folders out of search results, and _headers (root only) has Cloudflare check the game's files on every load and keep vendor/ for good. No build step.
- game/ files, in the order game/main.js loads them. Each imports what it uses from files above it; to use something from a file further down, or change a variable another file owns, use game.name (game/links.js: the owner shares it with share({...}) at its top). lint checks imports only go upwards. A new file goes in main.js below the files it uses. links, rules (the rules the game and the server share; test-build copies it to server/src/rules.js), core, parts (looks made of pieces from the data), land, nature, plants, world-build, items, people, world-items, you, needs, tips (the first-steps tips in the pill), inventory (the inventory's two tabs: Inventory, the tool bar and the grid, and Recipes, the craft mat with the recipe list), camera, moving (walking, pathfinding, task queue, autopilot), placeables (campfires and other placed things, stations, Pack up and Take apart, farm fields and crops), input (taps, tap menus, pause), screens (make your person, death, main menu, world picker), loop, online (server messages), admin (the dashboard and the admin's tools), others (other people, chat), society (societies, called camps in the game: the Camp panel, invites), admin-mode (the way into admin mode, its camera and taps), start.
- server/ (Cloudflare Worker pocket-life, one Durable Object "live"): src/index.js (storage, sockets, hello, message pipeline, tick), actions.js (one handler per player message: { when: any|alive|world, run }), persons.js, away.js, nature.js, line.js, placed.js (placed things like campfires and farm fields, and crops), admin.js, live.js (live settings), live-items.js (item and recipe numbers the admin changed), activity.js (the admin's Log), claims.js (campfire claims), societies.js (player groups sharing one claim), tasks.js (carrying on with a player's task list while they're away), accounts.js (Play on other devices: link codes; whoFor maps a device to its person), restore.js (Restore an earlier time), upgrades.js (saved data: the save format number and its upgrade steps, and making broken records safe; a change to what's saved = a new step + a check in tools/tests/upgrades.mjs), guard.js (reach, movement and flood checks), rules.js (a generated copy of test/game/rules.js: never edit it), shared.js (rules from game.json, LIMITS, helpers), needs.js. game.json and words.json are generated from content/*.json by `python3 tools/worlds.py test-build`.
- Server: save a connection's attachment with `this.attach(ws, me)`, never `ws.serializeAttachment` (who's connected is worked out once per message or tick and attach keeps it right).
- A new action = handler in server/src/actions.js (+ a LIMITS entry; check reach with guard.js and claims with claims.js), a task in game/moving.js (send it with sendAct), a tap menu entry in game/input.js (thingActions), and its entry in server/src/tasks.js (taskHow, taskMessage, cleanTasks) so it carries on while the player is away.
- tools/tests: checks that run the real server locally and play the game in Chrome (see its README), and quick ones that test the server's code with no browser (`cd tools/tests && python3 -c "import lib; lib.bundle()" && node admin_extras.mjs`, also live_items.mjs, stale_admin.mjs, cheats.mjs, societies.mjs, tasks.mjs, fade.mjs, forget.mjs, accounts.mjs, regrow.mjs, toolbar.mjs, farming.mjs, retire.mjs and upgrades.mjs; `run.py server_tests` runs them all). tools/release.sh releases.

## How to work
- Small updates, a couple of things at a time. Versions are Major.Minor.Patch (see docs/design/working.md): a test build only bumps "build"; patch goes up once per release; minor only when Luke says; 1.0.0 is the full game. Add short lines to the current version's devlog entry (shown in What's new) in "added" (+), "improved" (~) or "fixed" (−), with no name on the entry; fold a finished minor version into one grouped entry.
- Checks, kept quick (Luke, 22 Nov 2026: they were taking too long): `python3 tools/tests/lint.py` always. Test builds: only the check for the area you touched (plus `layout` if world layout code changed). Releases (Luke, 22 Nov 2026: too slow, publish straight away): no extra checks if each test build was already checked; just release. Everything (`run.py`, which skips `screens`) only after big changes. `screens` (screenshots of every screen, admin mode included; it takes a while) only when reviewing the look. Add a check when you add a feature. Only one check run at a time.
- Test first: push to main, Luke tries https://pocketlife.pages.dev/test/ (never give that link to players). After each change tell Luke in a few short lines what changed and what to try.
- Release only when Luke says ("release", "publish"): `sh tools/release.sh`, commit, push. Cloudflare Pages (project pocketlife) and the server both deploy from main within a minute or two.
- Run `python3 tools/worlds.py test-build` after changing content/*.json or test/game/rules.js (it writes test/game-data.json and the server's copies). lint.py says if you forgot, and checks the content for mistakes. The build number and the devlog are in content/version.json.
- Admin is admin mode (docs/design/admin.md): tap the version number on the main menu 5 times, then the admin password (asked every time; it's a Cloudflare secret, never in the repo). Also `?admin` on the address, and 5 taps on "Back soon" while maintenance is on. It works on a computer and a phone, and the admin is never a player. Never handle Luke's passwords or keys.
- When a decision is made, add it to its file in docs/design/ (and here only if it's a rule that always applies).
